A few orientation notes as you start building: Build vertically, not horizontally. Pick one feature (Log Set) and build its Model → Repository → Service → Presenter → View → wire-up end-to-end before moving on. Don't build all the repositories, then all the services, then all the presenters — you won't know if anything works until the very end. The interfaces/ folder is the contract layer. When you change a View method signature, you update the interface first, then both the view that implements it and the presenter that calls it. WebStorm will flag the mismatches. main.ts will feel like the messiest file. That's fine — that's where the wiring lives, and explicit wiring is better than hidden magic for a project you're learning on.
